## Limits and integration guidance

- Prefix safety intentionally retains an unfinished lexical token. A one-token response without whitespace waits for item/turn completion. This is explicit redaction-related buffering, not a claim of zero buffering or instant provider response; every complete prefix is eligible immediately. Final completion sanitizes the whole authoritative item, including the retained suffix.
- Sanitization still revisits the accumulated bounded answer. This change does not claim O(1) text processing or measured memory/RSS improvement. The 66-to-3 validation reduction is an operation-count improvement, not a measured end-user speed multiplier. Full-history preparation, per-user locks and optional catalog behavior remain existing code; no extra catalog/model RPC added.
- Legacy messages lacking phase retain the existing last-item fallback. Their missing protocol information cannot prove commentary/final equivalence. No keyword phase inference. Structured final messages take priority; unknown-only stream parity remains a QA gate.
- Existing product-identity shortcut was neither introduced nor used in measurement (fixture prompt is a document-summary request). No fake provider output is reported as real model speed.
- R1 QA's real Chromium activity/new-chat observations are baseline evidence only. Its combined refresh/spreadsheet case is PARTIAL; no full reload/Files acceptance is claimed. C owns Chromium/build/E2E; B did not start a browser or compete for that slot.
- No Melso execution, real model/account calls, external sends, production/client data mutation, Linux/Docker validation, build, push, CI publication or deployment. Automatic memory remains untouched and existing worker recovery tests remain in scope.
- F must integrate with A1/C, typecheck the final candidate and have existing QA revalidate real chat/reconnect/final activity. Transport journal ACK semantics and ownership interfaces are unchanged.
