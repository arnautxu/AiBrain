## Implemented changes

### Document readiness

The browser previously polled `document.body.innerText` and every link up to 40 times, and required at least 20 text characters plus a link. Valid blank pages, forms and canvas-style applications therefore waited about four seconds. Navigation now performs one in-document `DOMContentLoaded` wait and accepts the browser's `interactive` or `complete` state. Malformed, exceptional or still-loading results fail closed with `CHROME_DOCUMENT_NOT_READY`.

Real Chromium measurements used Chrome for Testing `151.0.7922.34` on macOS, a loopback HTTP fixture, three samples per page kind, and one fresh runtime for the matrix. Values include `agentNavigate` plus a real viewport capture.

| Page | Before median (n=3) | After median (n=3) | Readiness RPCs before / after |
| --- | ---: | ---: | ---: |
| Linked content | 1,296 ms | 62 ms | 6 / 1 |
| Form without links | 4,318 ms | 53 ms | 40 / 1 |
| Empty document | 4,192 ms | 45 ms | 40 / 1 |

A delayed chunked response and an HTTP redirect also reached their final page in the real-CDP test. These local measurements are diagnostic, not production latency claims.

### Browser input and attachment ownership

- Clipboard/IME text uses CDP `Input.insertText` once. This preserves multi-codepoint Unicode such as `Català ñ 日本語 👩🏽‍💻`; `dispatchKeyEvent` rejects that payload.
- Keyboard events now include the virtual key codes required by Chromium for Backspace, Delete, arrows, navigation keys, letters and digits.
- HTTP validation accepts useful clipboard whitespace and Unicode joiners while rejecting C0 controls, DEL, unpaired surrogates and payloads above 4,096 UTF-16 code units.
- Each mounted viewer receives an attachment UUID bound to the current browser-session UUID. Takeover, heartbeat and release are serialized per user. A late cleanup from an old viewer is an idempotent no-op and cannot release a successor's control.
- An attachment that finishes takeover after unmount sends a scoped compensating release. Pending input remains fenced to the original thread and is never replayed after an uncertain dispatch.

The real-CDP input regression changed from a rejected Unicode paste and ineffective Backspace (`a`, then `az`) to exact paste and deletion (`aCatalà ñ 日本語 👩🏽‍💻`, then the same value after adding and deleting `z`).

### Frame stream

Frame parsing now keeps an 8-byte header and a single bounded payload allocation instead of concatenating every incoming fragment. It also cancels an idle reader on abort and cancels the source after parser or callback failure. A single transport chunk may contain multiple individually valid frames whose combined size exceeds the per-frame limit.

A standalone parser diagnostic used three 1 MiB synthetic PNG-signature frames fragmented into 1 KiB chunks on Node `24.4.1`/macOS. Median decode time changed from 57.83 ms to 0.53 ms. This measures byte assembly only; it is not an FPS or UI responsiveness claim.
