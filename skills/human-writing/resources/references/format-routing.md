# Format routing

Apply the core workflow first, then adjust the delivery to the destination.

## Email and direct messages

- Put the reason for writing in the first useful sentence.
- Use plain text unless the destination supports formatting reliably.
- Keep greeting and sign-off proportional to the relationship.
- Make the requested action, owner, and timing clear without inventing urgency.
- Avoid summaries that repeat a short message.

## Social posts

- Start with the actual observation, result, conflict, or story, not a claim that nobody else understands it.
- Keep the platform's natural register and the writer's normal punctuation.
- Use line breaks for readability, not to turn every sentence into a dramatic fragment.
- Do not manufacture personal anecdotes, metrics, or screenshots.
- Avoid hashtag stacks, decorative emoji bullets, and generic engagement questions unless the user uses them.

## Landing pages and product copy

- Translate benefits into a supported mechanism, changed step, input, output, or constraint.
- Keep claims inside the evidence supplied by the product or user.
- Make headings and calls to action describe the real action.
- Preserve necessary legal, pricing, eligibility, and limitation language.
- Do not replace missing proof with polished adjectives.

## Articles, essays, and newsletters

- Preserve the writer's argument, digressions, tension, and uneven emphasis when intentional.
- Let sections have different lengths.
- Use examples and scenes only when sourced or clearly fictionalized.
- End on the strongest concrete implication rather than summarizing the outline.

## Reports and proposals

- Separate evidence, inference, recommendation, and open question.
- Keep numbers, sources, uncertainty, dependencies, and owners explicit.
- Use tables only for repeated fields or comparisons.
- Avoid promises about delivery or outcomes not established by the source.

## Technical documentation

- Preserve code, commands, paths, flags, identifiers, frontmatter, links, and API names exactly.
- Prefer the repository's real symbol over a synonym.
- Describe current behavior rather than narrating the latest diff unless writing a changelog or migration guide.
- Keep repetition when it prevents ambiguity.
- Neutral, plain prose can be the correct human voice.

## High-stakes text

For legal, medical, financial, security, incident, policy, or contractual writing:

- preserve every qualifier that carries scope, causality, risk, obligation, or uncertainty;
- do not add reassurance, guarantees, process commitments, or quality labels;
- prioritize precision over cadence;
- flag ambiguous source claims instead of smoothing them into certainty.

## Output contract

- If asked to draft: return the finished draft.
- If asked to edit: return the revised text; add a short change note only if useful.
- If asked to audit: return findings without rewriting.
- If editing a file: preserve non-prose content and report the changed files or diff summary.
- If embedded in another task: return only the artifact required by that task.
